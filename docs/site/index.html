Overview

HVL Interaktiv lets a teacher take one learning outcome and turn it into a short, accessible, interactive activity in under 30 minutes. The teacher can place it in Canvas, and walk into the next seminar knowing which misconceptions to address.

Everything in this specification serves that sentence. If a proposed feature does not shorten the path to a good activity, make it more accessible, or close the feedback loop between asynchronous and synchronous teaching, it is out of scope.

How asynchronous work fits around the seminar

HVL Interaktiv supports the asynchronous phases of a course. The synchronous session (samling) happens in the classroom or online; the activities prepare for it and consolidate after it.

PROD-001 Must S5 Create an activity from a learning-design pattern ○ Planned

An author can create a new activity by choosing a phase (Forarbeid, Mellomarbeid, Etterarbeid) and then a pattern. The H5P editor opens pre-filled with a pedagogically sound skeleton and guidance.

  • Acceptance: Every pattern in 04 §4 can be instantiated. The created content passes validateContent with zero errors before the author edits it, apart from placeholders that are deliberately flagged as needing input. Choosing blank activity is still possible.
  • Verify: Integration test that creates each pattern; e2e for J1.

PROD-003 Must S4 Check-and-publish quality gate ○ Planned

Activities have the states draft and published. Publish runs the universal design validator (UD-020) and the pedagogical hints (PED-020). Findings are listed in plain language with a Go to field link.

  • Acceptance: An error blocks publishing unless the author records an acknowledgement with a reason (e.g. "captions are being produced in Panopto"). Acknowledgements are stored, appear in insight and in the portfolio export, and are raised again on the next publish after 14 days. Warnings and hints never block.
  • Verify: Unit tests for state transitions; e2e for J1 step 5.

1. Problem and product promise

1.1 The problem we are solving

Asynchronous study at HVL often means students watch a 45-minute lecture recording or read a PDF that was uploaded to Canvas. This is passive. Research on multimedia learning and retrieval practice (see §4) shows that students learn more from short segments with frequent low-stakes questions. They also learn more when feedback explains why an answer is wrong, not just that it is wrong. Teachers face three practical barriers:

  1. Authoring friction. Interactive tools such as H5P have dozens of content types and many settings. Most of the settings do not help pedagogically, and several content types are not accessible. Teachers have little time and no guidance on which design actually works.
  2. No feedback loop. After setting asynchronous pre-work (forarbeid), a teacher cannot see what students struggled with before meeting them. The synchronous session therefore cannot respond to it.
  3. Institutional obligations. Universal design (WCAG / forskrift om universell utforming av IKT), GDPR, Canvas integration and documentation for the pedagogisk mappe are each solved separately, by hand, if at all.

1.2 Product promise

HVL Interaktiv lets a teacher take one learning outcome and turn it into a short, accessible, interactive activity in under 30 minutes. The teacher can place it in Canvas, and walk into the next seminar knowing which misconceptions to address.

Everything in this specification serves that sentence. If a proposed feature does not shorten the path to a good activity, make it more accessible, or close the feedback loop between asynchronous and synchronous teaching, it is out of scope.

3. Core user journeys

These journeys are the end-to-end acceptance tests of the product (Playwright, Session 6). Each step names the requirements it exercises.

J1 — Create from a pattern and place it in Canvas (Lars).

  1. In a Canvas module, Lars chooses Add item → External tool → HVL Interaktiv (Deep Linking, LTI-005).
  2. The picker shows Lars's activities and Create new. Lars chooses the phase Forarbeid and the pattern Short video with retrieval checks (PROD-001, PED-010).
  3. The H5P editor opens with an Interactive Video skeleton. It contains three question placeholders at 2–3 minute spacing, a summary task at the end, and guidance text in Nynorsk (H5P-002, H5P-008).
  4. Lars pastes a Panopto link, writes the questions and adds feedback for each wrong option.
  5. Lars clicks Check and publish. The quality check reports one error, a missing caption track, and one hint, that question 3 has no feedback for option C (PROD-003, UD-020, PED-020). Lars fixes both.
  6. The activity is published and returned to Canvas as a graded resource link (LTI-005, LTI-012).

J2 — Study asynchronously on a phone and resume (Amina, Jonas).

  1. Amina opens the activity from Canvas on a phone. It loads in under 3 s (NFR-001) and reflows to 320 px width (UD-008).
  2. Amina answers two questions. Wrong answers show ✗ Feil: and an explanation (UD-003).
  3. Amina closes the app and, the next evening, resumes at the same point (PROD-008, H5P-005).
  4. Jonas completes the same activity with NVDA and the keyboard only (UD-006, verified manually per UD-031).

J3 — Prepare the seminar from evidence (Lars, Ingrid).

  1. Wednesday evening Lars opens Innsikt → Før samlinga for the activity (INS-001).
  2. Lars sees that 148 students started and 131 completed. Question 2 had 38 % correct on the first attempt, and 62 % chose option B (INS-002, INS-003). Cells with fewer than five students are hidden (INS-006).
  3. Lars adds question 2 to the Bring to seminar shortlist and opens Thursday's session with it.

J4 — Document practice for the teaching portfolio (Ingrid).

  1. Ingrid tags each activity with phase, learning outcomes and a short didactic rationale (PED-030).
  2. Ingrid chooses Pedagogisk mappe → Export and receives a Markdown file and an accessible PDF. They contain the designs, each design's universal design status and anonymised aggregate results (MAPPE-001…MAPPE-004).

J5 — Govern the platform (Kari, Ola).

  1. Kari edits pattern guidance text in the studio's content files and opens a pull request; no code changes are needed (PED-011).
  2. Ola installs a new library version in staging, verifies it, then promotes it. Non-admins cannot install or update libraries, even through an uploaded .h5p file (H5P-006, SEC-003).

5. Functional requirements

PROD-001 Must S5 Create an activity from a learning-design pattern

An author can create a new activity by choosing a phase (Forarbeid, Mellomarbeid, Etterarbeid) and then a pattern. The H5P editor opens pre-filled with a pedagogically sound skeleton and guidance.

  • Acceptance: Every pattern in 04 §4 can be instantiated. The created content passes validateContent with zero errors before the author edits it, apart from placeholders that are deliberately flagged as needing input. Choosing blank activity is still possible.
  • Verify: Integration test that creates each pattern; e2e for J1.

PROD-002 Must S2 Exactly ten authorable content types

Authors can create only the ten content types in 01 §3.

  • Acceptance: See H5P-002.
  • Verify: Covered by H5P-002 tests.

PROD-003 Must S4 Check-and-publish quality gate

Activities have the states draft and published. Publish runs the universal design validator (UD-020) and the pedagogical hints (PED-020). Findings are listed in plain language with a Go to field link.

  • Acceptance: An error blocks publishing unless the author records an acknowledgement with a reason (e.g. "captions are being produced in Panopto"). Acknowledgements are stored, appear in insight and in the portfolio export, and are raised again on the next publish after 14 days. Warnings and hints never block.
  • Verify: Unit tests for state transitions; e2e for J1 step 5.

PROD-004 Must S3 Learners only see published activities

  • Acceptance: A learner request for a draft returns a friendly "not yet available" page (HTTP 404 to avoid revealing its existence). Authors can preview drafts.
  • Verify: Integration test.

PROD-005 Must S3 Place activities in Canvas

Authors can place an activity in a Canvas module, assignment or rich-content editor through LTI Deep Linking. See LTI-005.

PROD-006 Must S3 Share outside Canvas with Feide

An author can share an activity link that works outside Canvas. Viewers log in with Feide. Visibility is one of: only me / co-authors, everyone at HVL, or anyone with a Feide login.

  • Acceptance: Visibility is enforced by the permission system (H5P-006). Changing visibility takes effect immediately.
  • Verify: Integration tests per visibility level.

PROD-007 Should S5 Co-authoring and an institutional content bank

Authors can add co-authors (HVL staff found by name or Feide ID) and can publish an activity to the HVL content bank so that colleagues can duplicate and adapt it.

  • Acceptance: A duplicate keeps a link to its source and the original author's attribution. It never copies learner data.
  • Verify: Integration tests.

PROD-008 Must S2 Resume where you left off

A learner who leaves an activity and returns on any device resumes with their previous answers and position. See H5P-005.

PROD-009 Must S5 Formative defaults

For all patterns, Retry and Show solution are enabled, there are no time limits, and pass thresholds are informative rather than gatekeeping.

  • Acceptance: Pattern skeletons set the relevant behaviour fields. The hint rule PED-H07 flags activities where an author has turned these off.
  • Verify: Unit tests on skeleton parameters.

PROD-010 Must S6 Teacher insight before the seminar

Authors see aggregated, anonymised results per activity, designed to prepare the next synchronous session. See INS-* in 05.

PROD-011 Must S4 Formative-use notice

The editor and the Deep Linking picker show a short, dismissible notice. It says H5P activities are scored in the browser and are meant for formative work (undervegsvurdering), not exams.

  • Acceptance: Notice text exists in nn, nb and en. Dismissal is remembered per user.
  • Verify: Component test.

PROD-012 Must S1 Three languages, Nynorsk first

All UI is available in Nynorsk (default), Bokmål and English. H5P strings fall back from nn to nb to en. See H5P-008.

  • Acceptance: A test fails if any key is missing in a locale file.
  • Verify: Unit test for key parity.

PROD-013 Should S5 Safe editing of a published activity

When an author edits an activity that already has learner state, the editor warns that structural changes (adding, removing or reordering questions) reset saved progress. It offers Save as new version.

  • Acceptance: Existing learner state is invalidated only when the author confirms. Insight separates results by version.
  • Verify: Integration test.

PROD-014 Could S6 Spaced-retrieval suggestion

After publishing an Etterarbeid activity, the author is shown suggested repetition dates (for example +7 and +21 days) and a one-click copy to place in a later Canvas module.

  • Verify: Component test.

6. Non-functional requirements

NFR-001 Must S6 Performance

An activity page (player plus content) becomes interactive in ≤ 3 s at p95 on a simulated "Fast 4G" profile with 200 concurrent learners on one application node. API p95 is ≤ 300 ms excluding file downloads.

  • Verify: k6 or Artillery load test script in tools/load/; Lighthouse CI on the player route.

NFR-002 Must S6 Availability and recoverability

99.5 % monthly availability during the semester. Database backups run daily with 30-day retention. A documented restore is tested once per semester.

  • Verify: Operations runbook in docs/ops/; restore drill log.

NFR-003 Must S4 Mobile and assistive technology

Works on the last two versions of Chrome, Edge, Firefox and Safari, on iOS Safari and on Android Chrome, and with NVDA, JAWS and VoiceOver. See 03.

NFR-004 Must S1 Maintainability

Source files are ≤ 200 lines and each has a single responsibility. Every file follows DOCUMENTATION-STANDARD. CI runs typecheck, lint, tests and the traceability check.

  • Verify: npm run check:filesize, npm run spec:trace in CI.

NFR-005 Must S1 Open source licence

The repository is licensed GPL-3.0-or-later. This is required because @lumieducation/h5p-server is GPL-3.0-or-later. Dependencies must be GPL-3.0-compatible (for example MIT, BSD, Apache-2.0, ISC).

  • Verify: A licence check in CI against a GPL-3.0-compatible allow-list (npm run check:licences, D-029).

NFR-006 Must S6 Observability without personal data

Logs are structured JSON with request ID, route, status and latency. They must never contain names, e-mail addresses, Feide IDs, LTI sub values, ltik tokens, or answer contents. See DATA-009.

  • Verify: A unit test runs the log redaction function against a fixture of sensitive fields.

NFR-007 Must S6 Deployable on HVL or Sikt infrastructure

Docker images and docker-compose.yml for local and staging environments. Only EEA-hosted PostgreSQL, Redis and S3-compatible storage. No runtime calls to third-party CDNs (see DATA-011).

  • Verify: docker compose up smoke test in CI.

AUTH-001 Must S3 Feide OpenID Connect login (Authorization Code + PKCE)

The server is a confidential OIDC relying party, registered in the Feide Customer Portal (kunde.feide.no) under HVL (realm hvl.no (verify realm)). 6. Requirements — xAPI-to-AGS grade bridge

LTI-010 Must S6 Capture xAPI in the player

The injected client script (packages/hvl-h5p-theme/src/xapiBridge.ts, H5P-009) subscribes with H5P.externalDispatcher.on('xAPI', …). They never block or slow down the activity.

  • Verify: Unit test of the batching queue; Playwright test that statements arrive.

LTI-011 Must S6 Validate and store statements

/api/h5p/xapi validates statements with a zod schema. It accepts only verbs it uses (answered, completed, attempted, interacted, progressed). It checks that the object belongs to content the principal may view, and that 0 ≤ score.raw ≤ score.max and 0 ≤ scaled ≤ 1. It rate-limits each learner and activity to 120 statements per minute. Then it stores the minimal fields defined in DATA-012 and drops the rest of the statement (including actor.name and actor.mbox).

  • Verify: Unit tests for the schema; integration test for rate limiting.

LTI-012 Must S6 Publish scores to the Canvas gradebook (AGS)

When a statement concerns the root content (no subContentId), has the verb completed or answered, and carries result.score, the server applies the activity's attempt policy:

Policy (author setting)Score sent to Canvas
best (default)highest scaled score so far, ×100
latestlatest scaled score, ×100
mastery100 once the scaled score ≥ threshold (default 0.8), otherwise latest ×100

The result goes to a durable GradeSyncJob queue. A worker calls context.grading.submitScore(lineItemUrl, { userId: sub, scoreGiven, scoreMaximum: 100, activityProgress: 'Completed', gradingProgress: 'FullyGraded', timestamp }) with exponential backoff (up to 8 attempts in 24 h). Jobs are idempotent per (placement, learnerKey, attemptId). If the line item no longer exists, the job is marked orphaned and is not retried. The developer key needs the scopes …/lti-ags/scope/score and …/lti-ags/scope/lineitem.readonly (the latter detects orphaned line items). ltijs's grading service works from a LaunchContext, which lives as long as the ltik (24 h); a job still failing after that window stores what it needs to request a new client-credentials token itself, or is marked failed for the author to retry from a fresh launch.

  • Acceptance: Learning never waits for grade sync. Authors see a per-activity sync status (counts of sent / pending / failed) and can retry failed jobs.
  • Verify: Integration tests with a mock AGS endpoint (success, 5xx retry, 404 orphaned, idempotency).

LTI-013 Must S6 Score integrity is honest

H5P computes scores in the browser, so a determined student can forge them. The system therefore (a) labels AGS scores as formative in the line-item label suffix "(formativ)", (b) shows the formative notice (PROD-011), and (c) never presents these scores as exam evidence. Server checks in LTI-011 reduce accidental and casual manipulation. They are not claimed to prevent deliberate manipulation. On assignment_selection, Canvas uses the line-item label as the assignment name and overwrites the teacher's own name. Whether "(formativ)" belongs in the assignment name, or in the content item's description instead (with Canvas's preserveExistingAssignmentName extension), is a decision for HVL and ALU (verify).

  • Verify: Review item in the evaluator guide; unit test for the label suffix.

1. Teacher insight ("Innsikt")

The default view is Før samlinga ("before the session"): results since a chosen date (default 7 days ago), for one activity, in one Canvas context (or all portal users for that activity).

For each question (sub-content) the view shows: % correct on the first attempt, % correct on the latest attempt, and the number of learners. Items are sorted from hardest first. The question text is shown next to each item so the teacher does not need to open the editor.

INS-003 Must S6 Misconceptions

For choice questions, it shows how answers are distributed across options, with the teacher's own feedback text for each wrong option next to it. INS-005 Could S6 Video engagement

For InteractiveVideo, it shows the share of learners who answered each embedded interaction. This serves as a proxy for how far they watched. The spike in Session 6 decides whether H5P's progressed statements are reliable enough for a drop-off curve.

If suppression of one cell would let a hidden value be worked out from the totals, the next-smallest cell is suppressed too. The insight API has no endpoint that returns per-learner rows.

  • Acceptance: Property-based test: for random datasets, no API response contains a group smaller than k.
  • Verify: fast-check property test [INS-006] ….

INS-007 Must S6 Who can see insight

Owners and co-authors of an activity can see its insight. In LTI mode, authors of the launch context see results for that context only. Admins can see it only through an audited support action. Each view writes an audit event (DATA-007).

2. Data protection requirements

HVL is the data controller. Processing of learner data for teaching rests on GDPR Art. 6(1)(e) (task in the public interest: higher education). HVL's data protection officer must confirm this during the DPIA (DATA-005).

DATA-001 Must S1 Data inventory

docs/privacy/DATA-INVENTORY.md lists every stored field: purpose, category, legal basis, retention period and location. It must match the Prisma schema (apps/server/prisma/schema/). A CI script fails if a Prisma model or field is missing from the inventory.

  • Verify: npm run privacy:inventory-check.

DATA-002 Must S1 Pseudonymous learners

learnerKey = HMAC-SHA256(PSEUDONYM_SECRET[academicYear], source), where source is feide|<feide-id> or lti|<iss>|<sub>. The secret is held in the secret store, rotated per academic year, and destroyed when that year's data is purged. Learner rows store no names, e-mail addresses, Feide IDs, national ID numbers or raw LTI sub values. The one exception is the encrypted ltiSub in GradeSyncJob, which AGS needs; it is deleted 30 days after a successful sync.

  • Verify: Unit tests for key derivation; schema test asserting no PII columns on learner tables.

DATA-003 Must S6 Annual retention purge

A scheduled job runs on a configured date (default 15 August), for the academic year that has ended. It deletes XapiStatement, H5PUserData, GradeSyncJob and learner Identity rows older than the academic-year boundary plus 30 days, then learner User rows that have no Identity left (D-034), and destroys that year's pseudonym secret. Only aggregate snapshots that already satisfy k-suppression are kept, for the pedagogisk mappe.

  • Acceptance: A dry-run mode reports counts without deleting. Each run writes an audit event with the counts.
  • Verify: Integration test with time travel.

DATA-004 Must S6 EEA residency and encryption

PostgreSQL, Redis and S3-compatible storage are hosted in Norway or the EEA. All traffic uses TLS 1.2 or later. Storage is encrypted at rest. Backups are encrypted and retained for 30 days.

  • Verify: Deployment checklist (docs/ops/).

DATA-005 Must S6 DPIA input

docs/privacy/DPIA-INPUT.md describes processing operations, data flows (with a diagram), risks and mitigations. It cross-references this spec, so HVL's data protection officer can complete the formal DPIA. It records the Canvas developer key's privacy_level (anonymous) and its custom fields: in LTI 1.3, custom-field substitutions such as $Canvas.user.loginId release data whatever the privacy level, so adding one requires a DPIA update.

  • Verify: Evaluator review.

DATA-006 Must S4 Transparency for students

The player footer links to a short privacy notice in nn, nb and en. It says what is stored, why, for how long, and who can see what. In particular, teachers see only groups of at least k learners.

  • Verify: Component test; content review.

DATA-007 Must S6 Audit log

AuditEvent(at, actorUserId, action, targetType, targetId, details jsonb) records: insight views, exports, library installs and updates, permission changes, data-subject actions and purge runs. The audit log itself has no free-text personal data. It is kept for 2 years.

  • Verify: Integration tests assert events for each action.

DATA-008 Must S6 Data-subject requests

An admin-only tool takes a Feide ID or an (iss, sub) pair. It derives the learner keys for the retained academic years, then exports (JSON) or deletes that learner's data. Every use is audited.

Why this standard exists

HVL Interaktiv will be reviewed by people who did not write it: ALU learning designers, TeCopp administrators, security and privacy reviewers, and external evaluators. Most will not know H5P, LTI or Norwegian higher-education terms. They should be able to open any file and answer these five questions within a minute:

  1. What does this file do?
  2. Why does it exist? Which requirement in docs/specs/ does it fulfil?
  3. What must never go wrong here? (invariants, security or privacy assumptions)
  4. How do I know it works? Which tests prove it?
  5. What does it connect to? (callers and collaborators)

The rules below make those answers appear in predictable places. Wherever possible a tool checks them, so the documentation cannot quietly rot.

2. Checking one requirement end-to-end

Every requirement has an ID such as SEC-001. The same ID appears in the spec heading, in the code (Spec: header or @spec tag) and in test titles ([SEC-001] …). To verify one:

grep -n "SEC-001" docs/specs/*.md

# 2. Find the implementation and read its module header: what, why, invariants, tests
grep -rln "SEC-001" apps packages tools --include=*.ts --include=*.tsx

# 3. Run exactly the tests that claim to prove it                         (from S1)

# 4. Confirm the matrix agrees and nothing references an unknown ID
node tools/spec-trace/specTrace.mjs --check

Things to judge as you go: Do the acceptance criteria in the spec match what the test actually asserts? Does the module header's Invariants section match the code? Is every SECURITY:, PRIVACY:, A11Y: and PEDAGOGY: comment justified?

4. Evaluation rubric

For each area: what good looks like, where to look, and the red flags that should fail a review.

4.1 Pedagogical fitness: does it help teachers help students learn asynchronously?

  • Good: Teachers start from patterns (PED-010), not a blank list. Defaults are formative: retries on, no timers (PROD-009). Hints nudge towards short segments and explanatory feedback (PED-020). Insight answers "what should I address in the next session?" (INS-002, INS-003).
  • Look at: content/laeringsdesign/, apps/server/src/patterns/, apps/server/src/validation/rules/pedagogy/, the /laeringsdesign and /innsikt pages.
  • Red flags: Thresholds without a PEDAGOGY: reference. Hints that block publishing. Insight that ranks individual students. Pattern text that is not editable without code (PED-011).
  • Best evidence: Pilot results against the success measures in spec 00 §8.

4.2 Accessibility (WCAG 2.2 AA and HVL house rules)

  • Good: All colour comes from tokens, with a contrast test (UD-001). Feedback shows text and an icon (UD-003). Two-tone focus ring (UD-004). The validator blocks missing alt text and captions unless acknowledged (UD-021, UD-022). axe runs inside H5P iframes (UD-030). Manual screen-reader results are recorded (UD-031).
  • Look at: packages/design-tokens/, packages/hvl-h5p-theme/, docs/accessibility/.
  • Red flags: Hex colours outside the tokens package. outline: none without a replacement. !important without a WHY: comment. H5P.DragQuestion creatable anywhere.

4.3 Security

  • Good: Every SVG is sanitised on both upload paths (SEC-001). User files are served from a separate origin with CSP: sandbox (SEC-004). Non-admins can never install library code (H5P-006, SEC-003). An LTI launch never grants admin (LTI-004). The ltik is stripped from URLs and logs (LTI-003). Nonces are consumed atomically (LTI-002).
  • Look at: grep -rn "SECURITY:" apps packages, apps/server/src/security/, HvlPermissionSystem.ts, apps/server/src/lti/.
  • Red flags: LaissezFairePermissionSystem anywhere. localStorage holding an ltik. A ^-ranged runtime dependency. An npm audit exception without an expiry date.

4.4 Privacy (GDPR)

  • Good: Learners exist only as HMAC pseudonyms (DATA-002). No insight cell under k = 5 (INS-006, backed by a property test). Yearly purge with secret destruction (DATA-003). The data inventory matches the schema (DATA-001). Logs are redacted (DATA-009). No third-party requests (DATA-011).
  • Look at: docs/privacy/, apps/server/src/privacy/, apps/server/src/insight/, apps/server/prisma/schema/.
  • Red flags: Learner names or e-mails in any table. An endpoint returning per-learner rows to teachers. actor.name or mbox persisted from xAPI.

4.5 Interoperability (Canvas and Feide)

  • Good: A Playwright test passes with third-party cookies blocked (LTI-003). Deep Linking returns a valid signed JWT (LTI-005). AGS sync is durable, idempotent and visible to teachers (LTI-012). Feide roles follow the table in AUTH-002.
  • Look at: apps/server/src/lti/, apps/server/src/grades/, apps/server/src/auth/, the mock platform in tools/mock-platform/.
  • Red flags: Values marked (verify) in spec 02 still unverified at Session 3's gate. Grade sync happening inside the request path.

4.6 Code quality and documentation

  • Good: Every file has a module header that answers the five questions in the Documentation Standard. Tests read as specifications. Files are under 200 lines. Every decision is logged.
  • Red flags: Files called utils.ts or helpers.ts. Comments that restate code. TODO without a session or requirement reference. Hard-coded UI strings.

6. Known limitations (stated honestly)

  1. Scores are computed in the browser. H5P scoring cannot be made tamper-proof. HVL Interaktiv is for formative use only (LTI-013, PROD-011).
  2. Upstream accessibility. Some barriers are inside H5P content types and can only be fixed upstream. The conformance report (UD-040) lists them with issue links.
  3. H5P Core 1.28 with Lumi 10.0.4 is only partly verified (risk R-01). The S1 spike passed steps 1–2 (Node 24 with core API 1.28; core and editor files verified file by file). In S2, Core 1.28 runs on our player page in Chromium with the F3 styles, the Daylight tokens are active and overridable, and state resumes after a reload, but only with a synthetic content type: hub-api.h5p.org is still unreachable from the build environment (Q7), so Hub registration, the real seed packages and rendering the real content types remain open, and so does the 1.28-or-1.27 decision (R-01, to be recorded as D-047).
  4. Institutional reference material is not yet in the repository (see reference/README.md). Labels, brand colours and portfolio headings are therefore kept in configuration, so they can be corrected without code changes.
  5. No listening server yet. Session 2 builds the H5P routes (createH5pRouter) and tests them through Express with a test-only authenticator. The HTTP entry point, Feide and LTI authentication arrive in S3; the separate origin for user files, with signed URLs, in S3/S6 (D-045).
  6. Strict package versions. An author's .h5p import is refused when any library differs from the installed one in its patch version (SEC-003, Q9), which will refuse many packages exported elsewhere.

D-001 · Node.js 24 LTS instead of 22

  • Context: The plan specifies Node 22 LTS. ltijs@7.0.7, the current maintained release, declares "engines": { "node": ">=24" }. Node 24 is an LTS line supported until April 2028.
  • Decision: Target Node.js 24 LTS (.nvmrc, Docker node:24-* images, engines field).
  • Consequences: Development containers that ship Node 22 must install Node 24. Revisit once Node 26 becomes LTS.
  • Re-check: npm view ltijs@7 engines.

D-002 · Pin @lumieducation/h5p-server@10.0.4 and h5p-express@10.0.5

  • Context: The plan says "lock to version 10.1.0 or newer". No such version exists. The latest h5p-server is 10.0.4 (2025-03-08) and the latest h5p-express is 10.0.5.
  • Decision: Pin the exact versions (SEC-007). Watch the upstream repository for a release that fixes CVE-2025-7062 (see D-003).
  • Re-check: npm view @lumieducation/h5p-server versions.

D-003 · Own SVG sanitising and defensive file serving

  • Context: CVE-2025-7062 (stored XSS through uploaded files) affects h5p-server versions up to and including 10.0.4. 10.0.4 removed svg from the default allowlist, but it still identifies files by extension only. No fixed version is published. (CVE-2025-47828, which the plan also cites, is a different bug, fixed in 9.3.3.)
  • Decision: Defence in depth: @lumieducation/h5p-svg-sanitizer plus our own extra rules (SEC-001), magic-byte sniffing (SEC-002), a separate file origin with CSP: sandbox (SEC-004), and a narrowed allowlist.
  • Consequences: Slightly slower uploads. SVG stays usable for diagrams.
  • Re-check: OSV and NVD entries for CVE-2025-7062; the h5p-server CHANGELOG.

D-004 · Library installation is a GeneralPermission

  • Context: The plan restricts ContentPermission.InstallRecommended. In h5p-server 10.0.4 the enum is GeneralPermission (CreateRestricted, InstallRecommended, UpdateAndInstallLibraries).
  • Decision: Use GeneralPermission.*, admin-only (H5P-006).
  • Re-check: build/src/types.d.ts in the installed package.

D-005 · ltijs 7 with a PostgreSQL DatabaseManager

  • Context: The plan describes the ltijs 5 API (lti.setup(…, { ltiaas: true })) with ltijs-postgresql. ltijs 7 is a TypeScript rewrite: Provider, LaunchContext, a cookie-less ltik (24 h), and a pluggable 14-method DatabaseManager that ships with MongoDB only. ltijs-postgresql and ltijs-sequelize were last published in 2022 and target v5.
  • Alternatives: (a) ltijs 5 with sequelize: legacy and unmaintained. (b) Add MongoDB just for LTI: a second database to run and back up. (c) Implement DatabaseManager on Prisma/PostgreSQL: about 14 small methods.
  • Decision: (c), as PrismaLtiDatabaseManager (LTI-002). Keep ltijs behind our own LtiProviderFactory so a future library change stays local.
  • Re-check: npm view ltijs@7 dependencies; services/database-manager/database-manager.types.d.ts.

D-006 · Branching Scenario replaces Drag and Drop in the ten types

  • Context: H5P.DragQuestion is popular, but free 2-D dragging is a well-known barrier for keyboard, switch and screen-reader users (WCAG 2.1.1, 2.5.7). Case-based judgement is central to HVL's professional programmes.
  • Decision: Exclude DragQuestion from authoring, including as sub-content; include H5P.BranchingScenario (H5P-002).

D-007 · Two-tone focus ring instead of an orange outline

  • Context: The plan pairs coastal teal with a #FF9E1B focus outline. Measured contrast against white is 2.07 : 1, which fails WCAG 1.4.11 (needs 3 : 1). The plan also overstated two feedback contrast ratios (7.21 : 1 and 7.08 : 1 measured; both still pass).
  • Decision: outline: 3px solid HVL Mørk blå 2 (#004357, 10.82 : 1 on white; originally #003D4C, changed by D-017) with a 2 px white inner ring, which works on light and dark surfaces (UD-004). Contrast is tested in CI from the tokens (UD-001). #FF9E1B is not an HVL colour; HVL's orange is Oransje #EB6851. It clears 3 : 1 on white only narrowly (3.17 : 1), so it stays decorative.

D-008 · Formative use only

H5P scores in the browser, so scores can be forged. AGS scores are labelled formative and the UI says so (LTI-013, PROD-011). Exams stay in Wiseflow.

D-009 · Nynorsk first, with Bokmål and English fallback

HVL's main administrative language is Nynorsk. i18next uses nn → nb → en for both UI and H5P strings (H5P-008, PROD-012).

D-010 · Teachers see aggregates only, with k = 5

  • Context: Insight helps teaching decisions. Individual grades already exist in Canvas through AGS.
  • Decision: No per-learner insight endpoint. Suppress groups smaller than k = 5, with complementary suppression (INS-006).
  • Consequences: Very small classes see little insight. This is an accepted privacy trade-off, and k can be lowered to 3 by configuration.

D-011 · Learners are HMAC pseudonyms with yearly key rotation

learnerKey = HMAC(secret[academicYear], source). Destroying the secret at the yearly purge makes the remaining aggregates unlinkable (DATA-002, DATA-003). Resume state does not carry across the 1 August boundary. This is acceptable because the summer break falls there.

D-012 · One public origin, plus a separate origin for uploaded files

A reverse proxy serves Next.js and Express on one origin, which removes CORS and keeps the portal cookie first-party. User-uploaded files come from a cookie-less second origin, which limits the damage any file-borne script can do (SEC-004).

D-013 · Validator errors can be acknowledged rather than hard-blocking

Teachers sometimes publish while captions are still being produced (for example in Panopto). A hard block would push them to tools with no checks at all. An acknowledgement with a reason is stored, re-raised after 14 days, and visible in insight and the portfolio export (PROD-003, UD-022).

D-014 · English in code, Norwegian domain terms preserved

English makes the code reviewable by international evaluators and the open-source community. Domain terms such as forarbeid or laeringsutbytte keep their Norwegian form so teachers and ALU recognise them. They are explained in GLOSSARY.md (DOC-009).

D-039 · Our own sub-content policy on save (list items, DragQuestion, titles)

  • Context: Lumi's ContentScanner passes a list's array, not its parent object, to the SemanticsEnforcer for list items (ContentScanner.js:119). Text fields that are list items (for example H5P.Blanks questions) are therefore never sanitised (a CVE-2025-47828 regression), and a disallowed library that is a list item (for example a DragQuestion in a QuestionSet) is neither removed nor checked. Metadata titles are not sanitised either.
  • Decision: On save, our SubContentPolicy walks the params with the (altered) semantics, refuses with 403 any sub-library that the field does not offer and H5P.DragQuestion anywhere, sanitises list-item text with Lumi's own text rules, and sanitises the titles in main and sub-content metadata. A test pins the upstream behaviour so we notice when Lumi fixes it. Two gaps found in the S2 review are closed the same way: Lumi adds every library: "H5P.Name 1.2" value it finds, under any key, to the content's dependencies, so the policy refuses any such value the semantics walk did not reach (semantics/libraryReferences.ts); and H5P's "Rights of use" dialog shows metadata without escaping, so every metadata string is reduced to plain text, source is kept only as an http(s) URL, and a field that becomes empty is dropped. The verification pass after that review showed the dialog reads more than the semantics reach: h5p.js findCopyrights walks the whole tree, renders every metadata and file copyright object, and writes an image's path and the sub-content's alt into <img src="…" alt="…">. So semantics/rightsOfUse.ts cleans these anywhere in the parameters: metadata and copyright objects become plain text (sanitize-html with no tags, pinned as a direct dependency at the version Lumi uses; Lumi's own default for a field without tags still allows links and tables); a path with quotes, angle brackets, control characters or a scheme other than http(s) is refused with 400; and a straight double quote in alt becomes ”, because Lumi's sanitiser runs after ours and turns &quot; back into ". A second verification pass found three more ways out, now closed: WHATWG keeps a quote in a URL's host raw, so a source whose serialised form still holds ", ', <, > or a backtick is removed; the walk now continues inside metadata and copyright objects, as h5p.js does; and h5p.js joins arrays into the HTML, so an array path is refused, an array alt is emptied, and metadata nested deeper than the limit is dropped instead of kept as it was. A third, focused check (a sink audit of h5p.js and Chromium fuzzing with more than 60 variants) found no further way to run script, but five inputs that Lumi or PostgreSQL turned into a 500. They are now refused as the request's fault (400): text with U+0000 or a lone surrogate (storage/storableText.ts, also for learner state), nesting deeper than 256 levels before Lumi's recursive walks see it (semantics/nestingDepth.ts, also for an imported content.json), and values whose JSON type Lumi's scanners cannot read (paramsWalker.ts: text, list, group, library, file, image, video and audio fields); a sub-content library object without a usable toString is refused with 403 like any other.
  • Consequences: The walker (semantics/paramsWalker.ts) is reused by the S4 validator. Cleaning data for a renderer that does not escape is a list of known sinks, not a guarantee: the real ten types render their own copyright data (getCopyrights), so their sinks must be reviewed when the Hub packages arrive (Q7), and the player page gets a script CSP without 'unsafe-inline' in S4 (DATA-011), which stops injected handlers whatever their source.

D-044 · SVG sanitising rules and order

  • Context: SEC-001 asks to reject or strip DOCTYPE/ENTITY, scripts, event handlers, foreignObject, javascript:/data:text/html URLs and external references. Inkscape and Illustrator exports carry a public DOCTYPE, which is harmless without an internal subset.
  • Decision: An internal DTD subset or any <!ENTITY is rejected. A plain DOCTYPE and xml-stylesheet instructions are stripped. href/xlink:href may only point to a #fragment or a raster data:image/(png|jpeg|gif|webp). script, foreignObject, use, set, on* attributes and animations of href are removed (<use> can load an external document); @import and external url() are removed from styles. Order: our pre-check, Lumi's sanitiser, our stricter DOMPurify pass, and a final check that nothing forbidden is left. Benign SVGs must render identically in Chromium before and after (screenshot comparison).
  • Consequences: SVG files larger than 5 MB are refused. DOMPurify parses with the HTML parser (its XML mode returns nothing for a file with an <?xml?> prolog); that parser keeps xmlns but its SVG profile removes <use>, so a drawing that relies on <use> loses those parts (pinned in SvgSanitizer.test.ts). Lumi's profile is SVG only (no filter elements), so filter primitives such as feGaussianBlur are lost too, and DOMPurify removes ids that name document properties (title, blur, …), which breaks url(#…) references to them; a test pins all three losses. Our pass writes its result with XMLSerializer, and the final check parses it again as XML, as a browser does, and fails closed. Lumi alone let 15 of the 41 attack payloads in SvgSanitizer.bypass.test.ts through (13 once our pre-check had run); the added layers stop all of them.

D-050 · How we use ltijs 7: our router, our cache, our pages, our ltik checks

  • Context: ltijs 7.0.7 registers its routes through a pluggable HttpHandler; its own ExpressHttpHandler creates an Express app with cors({ origin: true, credentials: true }) and helmet, and Provider.listen() installs a SIGINT handler that calls process.exit(). Its RedisCacheManager uses ioredis. mongoose and ioredis load at import. getLaunchContext(ltik) does not check whether the platform is still active.
  • Decision: ltijs runs on our ExpressRouterHttpHandler (an Express Router); we never call Provider.listen(). SPEC-DEVIATION: our node-redis LtiCacheManager replaces ltijs's RedisCacheManager (LTI-001 wording); it caches only public JWKS and keysets. ltijs's own HTML gets a CSP with hashes of its inline scripts. Its default handlers are replaced by friendly pages. Our ltik resolver also checks platform.active. ltijs's OIDC recovery token (at most 10 minutes, grants nothing on its own) may sit in the frame's partitioned localStorage (stock Chrome) or, where storage is blocked and localStorage throws, in LTI Platform Storage; the ltik never does.
  • Consequences: mongoose, mongodb and ioredis are installed and loaded but never connected; an upstream issue asks ltijs to load them lazily. ESLint forbids importing RedisCacheManager, ExpressHttpHandler and MongoLegacyDatabaseManager. The S3 probes (test/lti/upstream/ltijsProvider.test.ts) also showed: ltijs copies the claims for the handler only after saveIdToken returns, so our storage filters a copy, never its argument; a resumed context (getLaunchContext) has only the stored claims, so the claim allowlist (D-052) must keep everything a later request reads (e.g. Deep Linking settings); and our handler must pass Express's lower-case req.headers through, or ltijs skips its Sec-Fetch-Site check without an error.

D-051 · LTI platforms and deployments from LTI_PLATFORMS; deployment IDs checked by us

  • Context: LTI-001 requires rejecting a launch with a wrong deployment ID. ltijs 7 checks only that the claim is a string, and its platform model has no deployment field.
  • Decision: A new table LtiDeployment(platformId, deploymentId). LTI_PLATFORMS (JSON in env) is synced at start-up: new platforms are registered (ltijs generates the tool key pair), endpoints updated, removed platforms deactivated, and each platform's deployments replaced.   • Consequences: Adding a Canvas deployment is a configuration change and a restart. Dynamic Registration (LTI-009) stays in S6.

D-052 · ltijs records: 10-minute nonces, 24-hour ID tokens with a claim allowlist

  • Context: LTI-002 says nonces expire after 10 minutes; the data inventory said 1 hour. ltijs stores the whole ID token, which can carry names, e-mail, lis identifiers and custom fields.
  • Decision: Nonces live 10 minutes (the inventory is corrected), matching ltijs's 600-second state. consumeNonce is one conditional DELETE, which is atomic. ID tokens live 24 hours and expired rows are never returned. The stored claims are an allowlist of what the launch needs; names, e-mail, lis, feide_login and unknown custom fields are dropped before storage. A cleanup job runs every 10 minutes under a Redis lease.
  • Consequences: The launch handler still sees the full claims in memory; only storage is minimised.

D-054 · The Feide subject is the Feide ID; Groups API failures fail closed

  • Context: DATA-002 derives the learnerKey from feide|<feide-id>, AUTH-005 compares Canvas's login ID with the Feide ID, and ADMIN_FEIDE_IDS lists Feide IDs. AUTH-004 allows sub or the Feide ID.
  • Decision: The Feide subject is the Feide ID (eduPersonPrincipalName, trimmed and lower-cased). D-055 · A stable identity key ring with HKDF purposes and a rotation rule

  • Context: Identity.subjectHash and AuthAuditEvent.ipHash need a keyed hash whose key does not rotate every year (the learnerKey's key does, D-011), and the rotation must be defined (PROGRESS S3).
  • Decision: IDENTITY_HASH_KEYS is a key ring id=base64,… whose first entry is current; HKDF derives the purpose keys identity-subject and auth-audit-ip. New columns Identity.subjectKeyId and AuthAuditEvent.ipKeyId record which key made a hash. Rotation: put the new key first; lookups try every key and re-hash a match in place at that login. Remove an old key after at least 13 months (learner rows are purged by then; a dormant staff member gets a new account). On compromise, rotate the same way at once.
  • Consequences: Rotation needs no downtime and no bulk re-hash.

D-056 · Secrets at rest are encrypted with AES-256-GCM from a key ring

  • Context: LTI-002 requires platform private keys encrypted at rest; D-021 requires the Feide ID token in the session encrypted; S6 stores GradeSyncJob.ltiSubEncrypted.
  • Decision: DATA_ENCRYPTION_KEYS key ring; AES-256-GCM with a per-purpose HKDF key and the purpose as AAD. Format 0x01 | keyIdLength | keyId | iv(12) | tag(16) | ciphertext. Used for LtiPlatform.privateKeyEncrypted, LtiAccessToken.tokenEncrypted, the session's Feide ID token, and in S6 for ltiSubEncrypted. Values are re-encrypted with the current key when they are next written.
  • Consequences: A database dump alone reveals no private key or token.

D-057 · Own Redis portal sessions, login transactions and a synchronizer CSRF token

  • Context: AUTH-003 asks for a Redis session behind an opaque __Host-hvli_sid cookie (idle 2 h, absolute 12 h) and CSRF protection; H5P-007 requires 401 for an H5P request without a valid token. Generic middleware (express-session, csurf) does not give these exact semantics, and csurf is deprecated.
  • Decision: Small own modules. Sessions in Redis under a hash of the session ID; the cookie is HttpOnly, Secure, SameSite=Lax, Path=/. A single-use login-transaction cookie (10 minutes) binds state, nonce and PKCE verifier to the browser, which prevents login CSRF. One synchronizer token per session, read from the X-CSRF-Token header, a csrf query value (H5P URLs) or a csrf form field; it is required on every unsafe method and on /h5p/ajax and /h5p/contentUserData for any method. A missing or wrong token is 401 hvl:csrf-invalid. Roles are computed at login only.
  • Consequences: A role change in Feide takes effect at the next login.

D-058 · H5P URL tokens and signed content-file URLs

  • Context: H5P-007 asks that H5P's AJAX and user-data URLs carry the ltik (Canvas) or a CSRF token (portal). Lumi's UrlGenerator puts the token unencoded, and contentFilesUrl receives no user, while H5P builds file URLs as contentUrl + "/" + path, so a query token cannot work there. D-045 puts signed file URLs in S3.
  • Decision: HvlUrlGenerator appends ltik or csrf, URL-encoded, from a new actor field urlToken. Content files are served from a public route /h5p/files/:grant/:contentId/*file, where the grant is an HMAC over contentId|expiry with URL_SIGNING_KEYS, valid for 12 hours and issued only by a render that passed the View check. An ltik in a query string is accepted only on /h5p/ajax, /h5p/contentUserData/*, /lti/play and /lti/deeplink; everywhere else it must be a Bearer header.
  • Consequences: Script inside content could read the token from its page; the S2 sanitising and the S4 CSP limit that. The separate files origin stays in S6 (D-045).
